CAVEATS ON RECORD (pre-flight P2 / A)
-------------------------------------
(a) Vacuous pin assertion. The reload block's first assertion --

      ok(boot.pinned === false || (boot.userScale === 1),
         'a pinned pipeline ignored the saved scale; ...')

    -- is vacuous in menuprobe. menuprobe never pins the pipeline: nothing here
    calls `setAdaptive(false, 1)`, so `_pinned` is always false at boot and the
    left disjunct short-circuits to true regardless of the pipeline's state.
    It cannot fail in this harness and must not be cited as proof of the pin.
    The pin property is proven elsewhere -- by the capture harness, which does
    call `setAdaptive(false, 1)`, and whose base-vs-after shotdiff aggregate
    sitting inside the same-tree control envelope is the evidence that the
    player's saved scale never leaked into a pinned capture. See
    diff-base-vs-after.json and diff-control.json in this directory.

    The same is true of `ok(dyn.resScale === 1, 'Off resets the adaptive
    term so the slider owns the buffer')` -- it is equally vacuous, because
    `_adapt` returns immediately while `ctx.paused` (RenderPipeline.js:342)
    and menuprobe runs the whole walk with a menu screen open, so `_resScale`
    is 1 before and after the Off click regardless of whether the reset code
    runs. The property is established out-of-harness instead, by seeding
    `_resScale = 0.75` / `_failedAt = 0.8` and calling
    `setRenderScale(0.9, false)` directly against the real prototype method,
    which produced `_resScale = 1`, `_failedAt = Infinity`, ratio `0.9` -- see
    the 2026-08-11 final review, finding C3.

(b) Menu preview canvases are a documented non-goal. The survivor-select
    portrait preview and the Logbook's model viewer (src/ui/Logbook.js:68) each
    construct their own renderer and set their own pixel ratio. The Render
    scale slider drives `RenderPipeline` only and does not reach them; they are
    small, static, off the frame budget, and deliberately left alone. A player
    dropping to 50% will see the world buffer shrink and the portrait canvases
    stay sharp. That is intended, not a leak.
